### Round 2 — document-wide — 2026-08-10 — both round-1 agents, resumed — **SPLIT** (1 blocking, author-introduced)

Gates reviewer **READY**, zero blocking. Correctness reviewer **NOT READY**, one
blocking — **and the blocker was introduced by the round-1 fix**, which is §3's
"a fix can introduce a blocker" in its purest form and the second time this corpus
has recorded one.

**The blocker: the insertion *index* and the inserted *point* were derived by two
different methods that disagree once a link already has a bend.** Round 1's fix
made the *point* transfer between the drawn and layout frames and left the *index*
coming from the drawn polyline's segment. Offsetting lengthens the outer segment
and shortens the inner one asymmetrically, so an interior vertex sits at a
different *fraction* of arc length in each frame — and splicing at the drawn index
puts a **spike** in the road, not a moved road. Resolved by deriving both from one
walk of the layout polyline, so they cannot disagree by construction.

The gates reviewer's own five blockers were all confirmed fixed in the file, and
it answered both questions put to it: Phase 1 is still one plan-mode pass with the
CSS in it, and Phase 2's gate is non-vacuous for nine of the ten mechanisms it
invents. **Its best finding was the tenth**, and it is a shape worth remembering:
two rows of §2.8's table claimed a test surface that cannot exist, because
`renderToStaticMarkup` cannot observe a prop — so a handle rendered *without* a
grab callback would have passed every automated assertion, and "the existing paint
assertions still hold" cannot fail if the CSS edit is simply skipped. Both now have
real gate items, the join asserted positively through `export.test.ts:embeddedCss`.

Also non-blocking and all accepted: **the prescribed grid-dot fix would have
rendered a quarter of a dot**, since a `<pattern>` clips to its tile and the
neighbours draw their own — Phase 3 now shifts the tile and leaves the dot
centred; §2.4 attributed the reversal guard to `segmentNormals` when it is the
second `Math.hypot(…) || 1`, inside `offsetPolyline`'s own interior-vertex branch,
and the `n₁` fallback does **not** "degrade to today's behaviour", since today
such a vertex is offset by nothing at all; §2.6's "same fraction" needed the
explicit arc-length conversion, `pointAlongPolyline` taking an absolute length; and
the claim that a `LinkView` is "absent for a link nobody has styled" is wrong —
`completeLink` and import both always write one, so the absent case is a
hand-edited or normalized document.

**One round-1 conclusion was re-examined and strengthened rather than reversed.**
Round 1 accepted that `.road-casing` rounds its join; folding it in meant reading
the rest of the stylesheet, which showed `.road-edge`, `.road-divider` and
`.lane-band` declare **no** join and take SVG's default `miter`. So the asphalt and
the paint on it are set to round and mitre the same corner — a second mechanism the
original finding had not reached, and the reason §2.4 was rewritten around two
mechanisms rather than one.

**A note on how this round ran**, because it bears on the record's reliability:
the correctness reviewer's first attempt terminated on an API session limit before

round was not closed on the gates reviewer's READY alone; the agent was resumed

### Round 1 — document-wide — 2026-08-10 — panel of two clean-room agents with repo access — **NOT READY** (7 blocking after dedupe)

A panel rather than one generalist, on §7.1's "large or high-blast-radius"
clause: Phase 1 changes a function with five consumers that runs on **every road
in every document**, and also the stylesheet that travels inside every exported
file. Lenses: correctness/grounding, and exit-gate testability/scope/cross-file
consistency.

**Round 0** (this episode = the whole document, no phase having shipped): does
this produce the observable, and is it the right one? **Yes.** Phase 2 produces it
directly — every figure whose roads must turn stops being a set of diagonal
chords — and Phase 3 changes how every figure reads rather than adding a feature
to one. Phase 1 produces none and argues that explicitly, on the ground that
shipping it after the bend makes the first corner anyone draws visibly broken.
The challenge recorded against it, and not re-litigated afterwards: is a straight
chord a legitimate *schematic* abstraction rather than a defect? **No** — the
project's own reference is a metro map, whose legibility comes from routing that
turns, and `CLAUDE.md` names connector bend points as presentation-layer content.

**Every finding was accepted; none rejected.** The three that reshaped the spec:

- **The central claim of §2.4 was half right, and the missing half inverted it.**
  The draft found that `offsetPolyline` is not a true miter and asserted the
  casing "miters correctly for free" because it is a stroke. It does not:
  `diagram.css:.road-casing` sets `stroke-linejoin: round`. Checking the rest of
  the stylesheet while folding the finding in made it worse and clearer —
  `.road-edge`, `.road-divider` and `.lane-band` declare **no** join and so take
  SVG's default `miter`, so the asphalt and the paint on it are set to round and
  mitre the same corner. The real defect is on the **inside** of the turn (5.85
  units of asphalt overhanging the edge line), the outside looks right today by
  accident, and **fixing the offset alone puts the paint 2.23 units outside the
  rounded asphalt** — a new artefact. §2.4 was rewritten around two mechanisms
  rather than one, and Phase 1 gained the CSS its scope had explicitly forbidden.
- **The spec was careful about the index and silent about the point.** §2.4 argues
  at length that a segment index transfers from the drawn polyline to the layout
  polyline, and never says which frame the stored *position* is in. They are
  `lateralShift` apart — 13.5 units on a default divided pair — so the literal
  reading steps the whole road sideways the instant a bend is minted, on precisely
  the divided-road case Phase 2's own dev pass names. Resolved in §2.6 with no new
  arithmetic: place by arc length on the drawn polyline into the layout one, then
  drag by a grab offset as a node and a sign already do.
- **Four compile-time sites, not three, and the fourth needed a design.** One
  reviewer added the proposed `Selection` arm to a copy of the tree and ran `tsc`
  rather than reasoning about it. `Inspector.tsx` fails on
  `findLink(doc, selection.id)` where the selection has narrowed to link-or-bend —
  so the panel needs a bend arm, which the spec asserted the existence of ("the
  Delete key and **the panel** both go through `deleteSelection`") while never
  specifying it. `zk-007` Phase 2 is the precedent for naming four sites and for
  saying outright that the Inspector has no test file.

Also blocking: **"a drag is one undo step" did not follow from the coalescing key
the phase added** — both reviewers traced it identically, `addBend` carrying a
`null` key pushes its own snapshot so one undo lands on the bend-inserted-but-
unmoved document; **Phase 1's "byte-identical" gate rested on a float identity
that is false** (a 3-4-5-slope collinear polyline gives `m · n = 0.999…9`, a
1-ULP shift, and `polylinePath` does no rounding) — the claim that actually makes
the phase invisible is that every polyline the app can produce is 2-point;
**Phase 2's gate could not fail for the drag threshold**, there being no
`Canvas.test.tsx`, so an implementation minting on pointer-down passed everything;
and **OQ-2 blocked Phase 2 while attached to no phase**, since `selectionValid` is
a `never`-checked switch that cannot compile without deciding it.

Two open questions were **resolved from code during the round**, per §4:

- **OQ-3, the miter limit, is 4, and the argument is an identity rather than a
  taste.** SVG bevels once `miterLength / strokeWidth` exceeds `stroke-miterlimit`,
  and that ratio is `1 / sin(ι/2)` — the same quantity as the offset's
  `1 / cos(φ/2)`, since `ι = 180° − φ`. So SVG's default of 4 makes the paint and
  the asphalt change behaviour at the same angle, 28.96°, which no independently
  chosen number would. Past it the two differ in kind (the offset clamps, SVG
  bevels), accepted because the alternative costs the vertex-count correspondence
  Phase 2 is built on.
- **OQ-2 is a one-line clear on undo/redo**, and the reason it is not the silent
  no-op the other four `Selection` arms enjoy: a stale *id* finds nothing and
  clears, while a stale-but-in-range *index* names a different bend.

**One rejected proposal of the spec's own**, refuted by a reviewer and recorded so
it is not re-made: OQ-1 argued a segment index needs no absent case because "a hit
always came from some segment". False — `nearestOnPolyline` `continue`s past
zero-length segments and returns its seed for an all-degenerate polyline, so a
non-optional index would report segment 0 for a hit that landed on nothing.

**Numbers this round re-derived**, so a later round can trust them: `LANE_PX` 9,
`ROAD_MARGIN` 3, `DEFAULT_LANE_WIDTH` 3.5 → a 2-lane arterial's `roadWidth` 21,
casing half-width 10.5, `RoadShape`'s `edgeInset` = `w/2 − 1.5` = 9, divided
carriageway offset 13.5; at a right angle the miters are 14.85 / 12.73 / 19.09.
The shipped `offsets a bent road along its whole length` fixture turns 36.8699°,
factor 1.0540926, moving its interior vertex 13.5 → 14.2302 — so the fix does
fail it, as the spec claimed. And the drawn grid dots sit at world `36i + 0.5/k`,
not on the `36i` lattice a snap would use — half a screen pixel off a dot of
radius 0.9, which would have made Phase 3 read as broken.

Both reviewers independently confirmed: no action writes `bends`; `diagramInner`
renders with no `interaction`; §2.5's `junctionArms` / `TAPER_MAX_BEND` /
`gorePair` consequences and the `strokeAllowance` no-op; the inline `LANE_PX * 4`
grid pitch bound to no constant; and the `include_str!` coupling.
