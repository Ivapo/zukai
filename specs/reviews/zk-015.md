### Round 2 — Phase 4 only — 2026-08-22 — same panel, all three resumed — **NOT READY**

**The round the loop caught the author's own fix**, and the third instance in
this record of a cure carrying the disease. Round 1's blocker was that moving the
editor to `/demo/` breaks the desktop app; the fix prescribed changing **both**
`devUrl` and `app.windows[0].url` in `tauri.conf.json`. All three reviewers
independently traced the pinned `tauri 2.11.5` and found that those two edits
*compose*: the resolver joins the window url onto `get_app_url()`, which returns
`build.devUrl` under `cfg(dev)`, so the pair yields
`http://localhost:1420/demo/demo/index.html` and a blank window.

**The sharper half is the trap in the other direction**, and it is why the spec
now carries a three-row truth table instead of a prescription: the resolver
skips the join for the literal string `index.html`, so a `devUrl`-only edit
passes `tauri dev` and ships a packaged app that opens the landing placeholder —
§2.6's own failure mode surviving inside the fix meant to cure it. The answer is
`app.windows[0].url` **alone**, `devUrl` untouched.

Three non-blocking findings mattered more than their tag suggests. `build:web`
had to be spelled `bun run build --base=/zukai/` rather than as a copy of
`build`'s body, because the duplicated form skips the `prebuild` wasm hook and
CI cannot survive it — `src-tauri/pkg/` is gitignored, so a fresh checkout has no
dynamic-import target. The favicon bullet claimed "one line each" while naming no
asset that exists. And after the entry move `bun run dev` serves the placeholder
at `/`, which silently invalidates `CLAUDE.md`'s Commands block — a
documentation regression nothing else in the gate would have caught.
